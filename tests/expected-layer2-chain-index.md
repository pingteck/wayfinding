# Meterline Platform

> A three-repo workspace: an ingest service, a rules engine, and a metrics exporter, wired
> in a line — ingest publishes to the rules engine, which the exporter scrapes.

## redirect-svc

- **Purpose:** Ingest service for meter readings. Normalises vendor payloads and publishes
  them onto the internal bus.
- **Role:** Ingest front door — the workspace's entry surface for vendor data, upstream of
  the rules engine.
- **Entry points:** The `quarryd` service binary — built via its make target, run against a
  config file.
- **Cross-repo links:** Publishes to `agents-only-svc` over the internal bus; never calls it
  directly.
- **Stack:** Go 1.25, Chi router, Postgres via pgx.
  _Layer-4 baseline only; Layer-3 profile TODO — see ${CLAUDE_PLUGIN_ROOT}/references/stack-profile-format.md._

## agents-only-svc

- **Purpose:** Rules engine. Evaluates thresholds against the ingest stream and raises
  notices.
- **Role:** Rules/eventing service — sits between ingest and the exporter.
- **Entry points:** The `beaconize` binary, run against a rules directory.
- **Cross-repo links:** Consumes the stream `redirect-svc` publishes to the internal bus;
  exposes an HTTP API that `readme-only-svc` scrapes.
- **Stack:** Go 1.25, embedded BoltDB.
  _Layer-4 baseline only; Layer-3 profile TODO — see ${CLAUDE_PLUGIN_ROOT}/references/stack-profile-format.md._

## readme-only-svc

- **Purpose:** Prometheus-style exporter that surfaces platform metrics for scraping.
- **Role:** Metrics exporter — the workspace's observability surface.
- **Entry points:** The `lattice-run` binary; listens on :9102 by default.
- **Cross-repo links:** Scrapes the HTTP API exposed by `agents-only-svc`.
- **Stack:** Go 1.25, zerolog for structured output, no external database.
  _Layer-4 baseline only; Layer-3 profile TODO — see ${CLAUDE_PLUGIN_ROOT}/references/stack-profile-format.md._

## Notes for graders / consumers of this oracle

This file is hand-authored ground truth for the neutral multi-repo fixture
`tests/fixtures/layer2-chain/` (stage it with `tests/stage-layer2-chain.sh`). It replaced an
oracle that *was* a real private workspace's index — see `tests/dogfood.md`. It is not
generated by any skill and must not be regenerated or overwritten by `bootstrap`/`onboard`;
skill output is graded *against* it, never replaces it.

**Every fact here is traceable to exactly one fixture file**, which is what makes the fixture
gradeable at all:

| where it came from | what only that file yields |
|---|---|
| `redirect-svc/AGENTS.md` (reached ONLY via the 11-byte `@AGENTS.md` redirect in its `CLAUDE.md`) | `quarryd`, `Chi`, `pgx` |
| `agents-only-svc/AGENTS.md` (no `CLAUDE.md` exists at all) | `beaconize`, `BoltDB` |
| `readme-only-svc/README.md` (the README tier) | `lattice-run`, `zerolog` |

**The deliberate omission.** `redirect-svc/README.md` names a `legacy-start` launcher and
marks it DEPRECATED. It is absent here on purpose: an index citing it read the README instead
of following the redirect. `grade-layer2-chain.sh` asserts that absence as a negative canary —
tripping it while passing the positive checks is *worse* than finding nothing, because it
looks authoritative and is wrong.

**The deliberate non-edge.** `redirect-svc` and `readme-only-svc` have **no** cross-repo edge,
and none is recorded. The both-endpoints rule is conditional — an asserted edge must be
reciprocated; an absent one must not be invented. A grader that requires every pair to be
connected would fail this correct index, so `grade-multirepo-index.sh` checks the conditional
form. (The oracle this replaced had two repos and one pair, so it could not exercise this.)
